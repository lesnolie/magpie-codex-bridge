原生 Codex + ChatGPT 协作

推荐方式 · Magpie Skills 安装 · 无需开启下面的 app-server

Skill

在 Magpie 的 Skills 中从 GitHub 导入 magpie-codex-collab 并指定给 Codex。Skill 使用原生 Codex 执行和已有的 Magpie MCP 连接，不会新开隧道，也不会复制项目文件。

首次从 ChatGPT Web 发起：提供当前对话的完整 URL，再通过 codex_collab_start 请求协作。尚无绑定时需要从目标 Codex Desktop 工作区先完成配对。

默认关闭。仅在唯一 Codex 窗口的输入框完整匹配启动指令，且找到可用的发送按钮时尝试发送。若不能自动发送，可通过 chat_session_status 查看 autoSubmit 的具体原因（如 Desktop 会话不匹配、窗口不可见、输入框不可读或发送按钮禁用）。无法验证时仍需手动发送；按钮被触发也不代表 Skill 已执行或对话绑定成功。可在下方“保存 Codex 设置”保存后重载插件。本功能不使用独立 CLI 或 app-server。

高级诊断 · 独立 CLI（非日常 Desktop 协作）

默认关闭。CLI 会在本地运行，最多等待 3 分钟；CLI 退出不代表 ChatGPT 浏览器协作成功。请先用只读测试目标验证。保存按钮位于下方 Codex 配置。

本机只读诊断

只有在此页面点击按钮，才会通过本地配置重载请求一次原生 CLI 测试；不会从远程 MCP 触发。始终使用 read-only 沙盒，不修改项目、提交或发布。

最多运行 3 分钟。同一时间只允许一次测试。退出码为 0 仅表示 CLI 正常退出；只有 Skill 完成项目与目标对话验证并写入本机会话绑定后，才显示绑定成功。

如果已经安全绑定原生 Codex 线程，同一对话的后续任务可使用 Codex Queue 投递，但入队并不等于已执行。每个请求都会防止自动重复派发。

专用 ChatGPT 标签页由 Codex 内置浏览器管理；只有该环境提供 control-in-app-browser 时才能自动发送审核消息。不同对话通过任务 ID、真实聊天 URL、MCP 项目验证后安全切换。

Skill 路径：skills/magpie-codex-collab。GitHub：查看安装源。

两个新工具：chat_session_status、chat_session_request_transfer。后者只提交切换申请，不会直接操纵浏览器。原生 Codex 关闭时也不会自动唤醒 ChatGPT。

确认允许 Codex 修改项目代码？

提升执行权限必须在本地明确确认。Magpie 不会自动同意 Codex 的权限提升请求，也不会提供直接修改项目的 ChatGPT MCP 工具。

需要在 Windows 上安装可执行的 Codex CLI（codex.exe 应可被插件宿主找到），并预先在本地完成模型与提供商配置。ChatGPT 账户自身的 MCP 执行权限仍可能阻止远程调用。

运行中的任务仍依赖本地插件进程；已完成任务的审核记录保存在本地。
